# Палеографическая расшифровка

Использовать для рукописных и плохо читаемых архивных документов. Сначала сохранить доказательно пригодное изображение по [archival-image-capture.md](archival-image-capture.md).

## Разделять слои работы

1. **Доказательный кадр** — неизменённый полученный файл или снимок просмотрщика.
2. **Собранное изображение** — детерминированная сборка кадров по координатам.
3. **Производная копия** — обрезка, поворот, оттенки серого, контраст или резкость с записанными параметрами.
4. **OCR-индекс** — машинный текст только для навигации.
5. **Ручная расшифровка** — чтение по изображению с явно отмеченной уверенностью.
6. **Нормализованное чтение** — отдельное современное представление, не подменяющее буквальную расшифровку.

Не перезаписывать предыдущий слой следующим. Не использовать генеративное восстановление букв как доказательный материал.

## Указывать охват

Не писать просто «дело проверено». Выбирать точное описание:

- **технический проход** — позиции открыты или сохранены, содержание не прочитано;
- **обзорный проход** — просмотрены заголовки, границы и крупные ориентиры;
- **кластерный проход** — искались заданные имена, родственные формулы и соседи;
- **построчная выписка** — последовательно прочитаны все строки указанного диапазона.

Для отрицательного результата указывать диапазон, уровень прохода, варианты поиска и качество изображения. Отсутствие OCR-совпадения и разреженная выборка не подтверждают отсутствие человека или записи.

## Консолидировать пакетную расшифровку

- Для последовательных сканов одного дела, документа или исследовательского вопроса вести один Markdown-файл расшифровки.
- Разделять его на секции по локальному файлу, позиции просмотрщика, архивному листу или этапу. Для каждой секции указывать источник, охват и уверенность чтения.
- Не создавать новый `.md` для каждого скана, батча, OCR-прохода или повторного чтения. Отдельный файл оправдан другим документом, делом, происхождением или независимой цитируемой единицей.

## Расшифровывать без подгонки

- Сначала читать строку и формуляр документа без опоры на желаемую родословную.
- Сохранять существенную орфографию, сокращения и порядок слов.
- Нечитаемое обозначать `[неразб.]`, сомнительное — `[чтение?]`, утрату — `[утрата]`.
- Вставленное по контексту заключать в квадратные скобки и объяснять основание отдельно.
- Не исправлять возраст, имя или родство внутри цитаты ради согласования с деревом.
- Различать буквальное чтение, грамматический разбор родственной формулы и идентификацию человека как три отдельных утверждения.
- Указывать файл, позицию, лист или оборот, сторону страницы и при возможности координаты фрагмента.

## Использовать OCR только как указатель

- Для семейных и приватных документов применять локальный OCR, если пользователь не разрешил внешний сервис отдельно.
- Сохранять OCR отдельно и указывать движок, язык, версию или существенные настройки.
- Проверять каждую сильную зацепку по изображению.
- Не переносить OCR-текст в GEDCOM и не повышать статус утверждения только из-за машинного совпадения.
- Не считать отсутствие слова в OCR отрицательным результатом поиска.

Для локальной пакетной подготовки изображений и запуска Tesseract использовать воспроизводимые команды из [image-processing-tools.md](image-processing-tools.md). Их JSON-манифесты фиксируют исходные контрольные суммы, параметры и результаты, но не превращают OCR или обработанную копию в первичный источник.

## Проверять ключевые чтения

Для имени, возраста, родственной формулы или заголовка, меняющих дерево:

1. Повторно прочитать увеличенный фрагмент в контексте соседних строк.
2. Сравнить спорные буквы с уверенными образцами руки на том же листе.
3. Проверить формуляр и синтаксис документа.
4. Сохранить альтернативные чтения и критерий разрешения.
5. По возможности получить независимое чтение без подсказки предпочитаемого варианта. Повторное чтение тем же исследователем по тому же изображению не считать независимым подтверждением.

Вносить результат в GEDCOM только после отдельной идентификации человека и достижения статуса `CONFIRMED`.
