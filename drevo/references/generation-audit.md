# Аудит поколений

Использовать, чтобы проверить доказательную непрерывность прямой линии или всего набора предков выбранного человека. Аудит отвечает не на вопрос «есть ли люди в дереве», а на вопрос «чем подтверждён каждый переход родитель–ребёнок».

## Собрать структурный черновик

Сначала проверить канонический файл:

```sh
python3 <путь-к-скиллу>/scripts/validate_gedcom.py family-tree.ged
```

Для всех предков до заданной глубины:

```sh
python3 <путь-к-скиллу>/scripts/assemble_generation_audit.py family-tree.ged \
  --root @I1@ --generations 6 \
  --output research/reports/YYYY-MM-DD_ветвь_аудит-поколений.md
```

Для заранее выбранной прямой линии передать последовательность от потомка к предку:

```sh
python3 <путь-к-скиллу>/scripts/assemble_generation_audit.py family-tree.ged \
  --path @I1@,@I2@,@I7@,@I15@ \
  --output research/reports/YYYY-MM-DD_линия_аудит-поколений.md
```

По умолчанию имена потенциально живых людей скрыты. Показывать их через `--include-potentially-living` только в приватном локальном отчёте, когда это разрешено правилами проекта. Существующий файл не перезаписывается без `--force`.

## Понимать автоматические поля

- Поколение `0` — исходная персона, `1` — её родители.
- В режиме всех предков «мест» означает теоретические позиции `2^n`; повтор одного предка в нескольких позициях учитывается как схлопывание родословной.
- Если у человека неоднозначно записано несколько родительских семей, режим всех предков останавливается. Выбрать доказуемую линию явно через `--path`; не разрешать неоднозначность автоматически.
- `SOUR` семьи, записи человека и события рождения выводятся как кандидаты. Само наличие ссылки не доказывает, что источник буквально подтверждает нужное родство.
- `НЕ ОЦЕНЁН` — обязательный исходный статус. Сборщик не присваивает доказательные статусы.
- Ближайший структурный разрыв — навигационный приоритет, а не доказательство отсутствия родителей в реальности.

## Проверить аудит содержательно

1. Проверить каждую строку перехода как отдельное утверждение.
2. Открыть перечисленные источники-кандидаты и установить, называют ли они обоих людей и их роли.
3. Проверить идентификацию людей отдельно от чтения родственной формулы.
4. Присвоить `CONFIRMED`, `PROBABLE`, `HYPOTHESIS` или `CONFLICT` по [evidence-and-identification.md](evidence-and-identification.md).
5. Вынести боковые связи и кластерные признаки отдельно: они помогают идентификации, но не заменяют прямой документ.
6. Разделить конфликты дат и событий от конфликта самой родственной связи.
7. Назвать ближайший разрыв и минимальный источник, достаточный для его закрытия.
8. Записать решение по GEDCOM; не добавлять новое поколение через неподтверждённый переход.

Обновлять один аудит выбранной линии, пока его область не изменилась семантически. Новый файл оправдан другой исходной персоной, другой ветвью или независимым исследовательским вопросом.
